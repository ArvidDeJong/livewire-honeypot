The conventions shared by every darvis package (language, releases, CI, docs site, Boost guidelines, public API policy) are in [../CLAUDE.md](../CLAUDE.md); this file only holds what is specific to this package.

## Package overview

`darvis/livewire-honeypot` is a Laravel package (PHP 8.2+, Laravel 11/12/13, Livewire 3/4) that protects forms with a hidden bait field and a minimum fill time. Host apps consume it via Composer; this repo only contains the library.

- Namespace: `Darvis\LivewireHoneypot\` → `src/`
- Service provider auto-registered via `extra.laravel.providers` in [composer.json](composer.json)
- Config key: `livewire-honeypot`

## Architecture

- [HoneypotService](src/Services/HoneypotService.php) is the only place that reads the package config (`fieldName()`, `minimumFillSeconds()`, `maximumFillSeconds()`, `tokenLength()`); don't call `config('livewire-honeypot.…')` elsewhere. `check()` holds the shared validation logic. `validate()` (controllers) and `HasHoneypot::validateHoneypot()` (Livewire) both delegate to it. Don't duplicate checks in the trait.
- Every rejection goes through `reject()`, which dispatches `Events\SpamBlocked` and throws a `ValidationException`.
- [HasHoneypot](src/Traits/HasHoneypot.php) marks `hp_started_at` and `hp_token` as `#[Locked]`. Before 1.1.0 the blade bound them with `wire:model`, so a client could set its own start time. Never bind them again. Tests travel in time instead of `->set()`.
- Plain forms get a signed token: `random.timestamp.hmac(app.key)`. `validate()` reads the start time only from it; a posted `hp_started_at` is ignored on purpose. Don't add an unsigned fallback, that reopens the bypass. `verify()` tries `app.key` and then `app.previous_keys`, and returns the key that matched, because the bait name is derived with that same key. An empty `app.key` throws `MissingAppKeyException`: an HMAC with an empty key can be forged. Plain forms expire after `maximum_fill_seconds` (replay protection); Livewire forms don't, on purpose, so an open tab doesn't lose its input. The token is no longer length-checked; `token_min_length` is gone.
- The bait `name` is generated by `baitName()` from `BAIT_WORDS`. Every word must stay clear of browser autofill heuristics (name, email, url, website, company, address, phone, ...), otherwise autofill blocks real visitors. In plain forms the name is derived from the token so the server can find it; `field_name` is the fallback key and the error key.
- `<x-honeypot />` is the class component [View\Components\Honeypot](src/View/Components/Honeypot.php); [honeypot.blade.php](resources/views/components/honeypot.blade.php) holds only markup. Laravel calls `render()` before the attributes are set, so the one attribute-dependent value (the `wire:model` binding) is read in the view. Livewire mode requires both the shared `$__livewire` and a component that uses `HasHoneypot`; a plain form inside another Livewire component needs the signed token. It shows the error outside the hidden wrapper and guards `$errors`, which is missing without the web middleware.
- The wrapper is hidden with screen-reader-only CSS (clip-path), not `left:-10000px` or a recognisable class name. With a CSP nonce (`Vite::cspNonce()` or the `nonce` attribute) it uses a `<style nonce>` block and `wrapperClass()`. That class and the style content must stay identical across renders: a Livewire update may carry another nonce, and a changed style block would be checked against it.

## Conventions

- `docs/honeypot-autofill-test.md` holds a self-contained tool (style and script blocks that Kramdown passes through); keep its JavaScript free of `{{` and `{%`, use `/* */` instead of `//` comments and end every statement with a semicolon (Just the Docs compresses each page to one line), and test it in a browser after changes.
- Keep the public API compatible within 1.x: `generate()`, `validate()`, `validateHoneypot()`, `resetHoneypot()` and the `hp_*` properties.
- `tests/Feature/BoundariesTest.php` pins the exact boundaries, the config defaults and the derived bait name and wrapper class. The golden values there must only change when you deliberately change the derivation, which invalidates every form that is already open.
- Translations live in `resources/lang/{de,en,es,fr,nl}`; add every new key to all five.
